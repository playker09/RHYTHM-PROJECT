# RHYTHM 패턴 툴

`RHYTHM-PROJECT`(Godot 4) 전용 채보 에디터. **`PatternTool.exe` 를 실행하면 끝.**
기준 문서: `PATTERN_TOOL_GUIDE.md` (게임 코드는 수정하지 않음).

## 실행
- `PatternTool.exe` 더블클릭 → 앱 창(Edge/Chrome)이 열립니다. 창을 닫으면 프로그램도 종료됩니다.
- 게임 폴더(`project.godot` 이 있는 곳)는 자동으로 찾습니다 (exe 주변 / 상위 폴더 / 형제 `RHYTHM-PROJECT`).
  못 찾으면 폴더 선택창이 뜨고, 하단의 `게임: …` 을 클릭하면 언제든 바꿀 수 있습니다. 설정은 `%LOCALAPPDATA%\RhythmPatternTool\` 에 저장됩니다.
- 곡마다 난이도 3개(EZ / NM / HD) = `<게임>/charts/<곡폴더>/ez.json`, `nm.json`, `hd.json`. 위쪽 **EZ/NM/HD 버튼**으로 전환합니다 (점선 = 아직 없는 난이도, 열어서 저장하면 생김).
- 저장하면 지금 난이도 파일에 바로 써집니다 (이전 파일은 `nm.json.bak` 처럼 `.bak`). `meta.difficulty` 는 파일에 맞춰 자동으로 채워집니다.
- title / artist / audio 는 저장할 때 같은 곡의 다른 난이도 파일에도 맞춰집니다. level, offset, BPM, 노트는 난이도마다 따로입니다.
- 새 난이도를 열면 다른 난이도의 곡 정보·offset·BPM 을 가져오고, `곡 · BPM` 탭의 **`XX 노트 복사해 오기`** 로 노트를 통째로 가져와 깎거나 더할 수 있습니다 (Ctrl+Z 가능).
- 예전 단일 `chart.json` 은 NM 으로 열리고, 저장하면 `nm.json` 이 됩니다 (`chart.json` 은 그대로 남으니 확인 후 지우세요).

## 조작
| 키 | 동작 |
|---|---|
| 1 / 2 / 3 / 4 / 5 | 선택 / 탭 / 홀드(드래그) / 플릭(Tab: 방향) / 필드 |
| 필드 | 클릭으로 키프레임 추가 → **Enter** 확정, 우클릭·Backspace 마지막 취소, Esc 취소, Alt+휠 폭 |
| 휠 / Shift+휠 / Ctrl+휠 | 스크롤 / 스냅 단위 이동 / 줌 |
| Space | 재생·정지 (효과음 on/off, 0.5×~1× 속도) |
| `[` `]` | 스냅 1/4 ~ 1/64 |
| Ctrl+Z / Y, Ctrl+C / V, Ctrl+A | 되돌리기·다시, 복사·붙여넣기, 전체 선택 |
| M, Shift+↑↓, Del, 우클릭 | 좌우 반전, 선택 노트 시간 이동, 삭제 |
| Ctrl+S | 저장 |

## 자동 생성 (✨ 자동 생성)
- 노래를 분석해서 **지금 난이도(EZ/NM/HD)의 초안**을 찍습니다 (`web/autochart.js`). 만든 뒤 고쳐 쓰는 용도. Ctrl+Z 로 통째로 되돌릴 수 있고, 누를 때마다 배치가 조금씩 달라집니다.
- 분석: 소리가 터지는 지점(onset), 저음(킥/베이스)으로 BPM·첫 박 추정, 음량, 음색(밝을수록 오른쪽 레인).
- BPM: 직접 넣은 BPM 이 있으면 그대로 두고(반/두 배로 읽히면 알려 줌), 기본값 120 이면 추정 BPM 을 씁니다. **첫 박 위치 맞추기** = `meta.offset` 을 바꿔 박자선을 노래 박에 맞춤 (노트가 없을 때 기본 켜짐).
- 생성: 격자(EZ 4분 / NM 8분 / HD 16분) 위 센 소리부터 목표 밀도만큼, 같은 레인 빠른 연타 금지, 소리가 길게 이어지면 홀드, 센 박 동시치기(NM/HD), 시끄러운 마디에 Field + 센 박에 Flick. 밀도 슬라이더, 범위(전체 / 지금 위치부터), 레벨 추정.
- 박자가 바뀌는 곡(BPM 변화)은 BPM 을 직접 넣어 두면 그 격자를 따릅니다. 추정은 단일 BPM 만 합니다.

## 플레이 테스트 (🎮 테스트 / T)
- 빨간 판정선 위치에서 시작합니다. **왼쪽 시간 눈금을 클릭하면 그 위치부터 바로 시작**합니다 (테스트 중에 누르면 거기로 점프). 노래가 함께 나오고(시작 지점 1.5초 전부터), 판정 시계는 노래 재생 위치에 맞춥니다.
- 오른쪽 = 게임과 같은 구도의 하이웨이(판정 범위·Field 이탈 유예·Flick 규칙 동일, `web/playtest.js`). 왼쪽 = 흰 재생선이 올라가다가 화면 위 30%에서 멈추고 채보가 따라 내려옵니다. 빨간 점선 = 테스트 시작 지점.
- 조작: A S D F, 마우스(하이웨이를 클릭하면 마우스가 잡힘, 게임처럼 상대 이동, Esc 로 풀림). R 다시, Space 끝내기, Esc 닫기(편집 위치는 시작 지점으로 돌아감).
- **테스트 중에도 왼쪽에서 그대로 편집**할 수 있습니다 (도구/단축키/Ctrl+Z 모두). 아직 안 지나간 노트는 바로 새 채보로 판정되고, 점수·콤보는 이어집니다. 휠/방향키는 화면만 움직이고(1.5초 뒤 다시 따라감) 재생 위치는 그대로입니다. Ctrl 없이 누른 A S D F 는 레인 입력입니다.
- 배속/감도는 처음엔 게임 설정(`%APPDATA%\Godot\app_userdata\<프로젝트 이름>\settings.cfg`)을 읽고, 툴에서 바꾸면 그 값을 기억합니다. `오토`를 켜면 완벽한 플레이를 구경만 합니다.
- 시작 지점 1.5초 전 이후에 시작하는 노트만 판정합니다. 점수/정확도는 그 구간 기준입니다.
- 브라우저 오디오 지연은 게임과 다를 수 있습니다. 최종 싱크 확인은 게임(F5)에서 하세요.

화면: 왼쪽 = 공중(flick/field, x 0~1), 오른쪽 = 바닥 4레인(A S D F). 시간은 ms, 위로 흐릅니다.
x/center 는 5% 단위로 스냅(Alt 누르면 1%). 파형은 `meta.offset` 이 반영된 위치에 그려집니다.

## 저장 전 검사 (PATTERN_TOOL_GUIDE.md 4·6절)
- **오류(저장 불가)**: lane 0~3, hold `end > time`, flick `x` 0~1·`dir` left/right, field 키 2개 이상·시간 오름차순·`center/width` 0~1·필드끼리 겹침 금지, bpm > 0.
- **경고(저장 가능)**: 같은 레인 tap/hold 겹침, flick 간격/방향 급변, 필드 첫 center 도달 난이도, 오디오 길이 초과.
- 서버가 저장 직전에 `ChartLoader` 규칙을 그대로 모사해서 **로더가 버릴 노트가 하나라도 있으면 저장을 거부**합니다.
- 검사 탭에 tap/hold/flick/field 개수와 **총 판정 수**(hold/field tick = 1/8박 규칙, 마지막 tick = 끝 시각)가 표시됩니다.
- 경고 기준 중 `FLICK_MIN_GAP_MS`, `FLICK_REVERSE_GAP_MS`, `MAX_CURSOR_SPEED` 는 게임 코드에 없는 휴리스틱입니다 (`web/core.js` 상단).

## 새 곡
`＋ 새 곡` → 폴더 이름/제목/BPM/오디오 입력. NM 채보로 시작합니다. 새 오디오는 **Godot 에디터에서 프로젝트를 한 번 열어 import** 해야 게임에서 로드됩니다.

## 개발
```
python launcher.py --no-browser      # 서버만 (URL 이 콘솔에 출력됨)
python tests/run_tests.py <게임폴더>      # 코어(JS) + 서버 테스트 (샘플 = charts/sample/nm.json)
python tests/run_ui_tests.py <게임폴더>   # 실제 마우스 조작 UI 테스트 (임시 폴더에서 실행)
build_exe.bat                        # PatternTool.exe 재빌드 (pip 로 pyinstaller 설치)
```
구성: `launcher.py`(로컬 서버 + 창 실행 + charts API) · `web/core.js`(포맷/타이밍/검증/통계) · `web/app.js`(UI).
서버는 127.0.0.1 에만 열리고, 실행마다 바뀌는 토큰이 없으면 모든 요청을 거부합니다.
